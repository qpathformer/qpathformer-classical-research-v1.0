# Research release policy

Proposed policy. A release is an owner-approved snapshot of identified papers and supporting materials. The scientific paper, research approach and repository rules are distinct documents. The [research approach](RESEARCH_APPROACH.md) must be linked in the release notes and included under release docs; it is excluded from the main paper.

## Consolidated v1 release

The main findings paper is Q-Pathformer Routed States: Classical Models and Quantum Circuit Simulation, supplied as Word and PDF. The separate Three-State Architecture and Experimental Specification is its companion. The papers carry research edition v1.0 without editorial draft labels; covers are intentionally clean. Scientific proposal/validation limits remain explicit. The Papers ZIP contains these two papers, ten unchanged supporting study reports and the unchanged QPATH-ARCH-001 original from Git. Original source bytes and exact source-backed changes remain in the private owner record.

The consolidated release ZIP adds a separate docs directory with the research approach, governance, contribution guidance, reproducibility requirements and publication notice. Historical reports stay individually identified. Do not treat an assembled archive as a new experiment or an empirical endorsement of the architecture proposal.

The superseded GitHub v1.0 packaging release has been removed at the owner’s request. Its complete metadata and all six assets are preserved with verified identities in the private owner archive. The Git tag and historical repository provenance remain unchanged. The consolidated research-v1.0 release is now published within the private repository and is marked Latest. Its existing tag and sealed assets remain unchanged. Any later packaging edition must use an unambiguous identity and reviewed source commit; do not force-move or repurpose historical tags.

Keep the repository private and research-v1.0 as Latest throughout this final-check preparation. Public visibility follows the owner's final review of the selected material. The current paper-label and licensing updates are prepared as a distinct replacement under research-v1.0-20261031, with the displayed title and filenames staying v1.0. On approved publication, mark research-v1.0 as superseded, retain its assets and tag, and make the replacement Latest. A README/navigation update alone does not require a new release. If a later package changes, record its separate edition, destination and intended Latest designation; preserve earlier sealed assets.

## Publication checks

Confirm final paper identity and title; complete substantive review; preserve supported claims and limitations. The standalone research approach original prose has its own adopted CC BY 4.0 scope. The owner has adopted the current controlled original paper, cover and helper selection under CC BY 4.0; its exact scope and exclusions are recorded in RESEARCH_V1_CONTENT_LICENSE_SCOPE.json. Check retained and third-party notices separately. Existing report grants do not automatically license the new findings manuscript, architecture companion or all helper files.

Review the exact publication snapshot and every included asset. For an existing repository, examine all reachable Git history and branches, tags, releases, issues, PRs, workflow logs/artifacts, LFS objects and linked external storage. Replacing the current README or removing one release does not conceal earlier content. Preserve private records outside the public distribution. If a full public disclosure review cannot clear the existing history, prepare a clean public distribution while retaining a private canonical archive.

Verify manifests, checksums, links, licence notices, authorship and reading order. Verify public/private separation using a non-member account before sharing access. Review scientific claims and safety results separately from archive integrity. Publish only after the owner approves the exact hashes and destination.

## Later editions

Keep private v2.0 development and Strategic material separate from its eventual curated public edition. Owners decide what passes disclosure review and what stays private for v3.0 or later. Repeat contribution eligibility and owner approval for the next private cycle, rechecking participation scope rather than automatically carrying access forward. Retain the [publication notice](PUBLICATION_NOTICE.md) in each edition.
